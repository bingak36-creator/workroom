# 아키텍처 결정 — 0.3.0-rc.1

## 역할 분리

ChatGPT 또는 다른 MCP 호스트가 대화·모델·정책을 담당합니다. Workroom은 승인된 로컬 파일, 실행 요청, 작업 체크포인트만 관리합니다. ChatGPT 화면을 읽거나 모델을 직접 실행하지 않습니다.

```text
MCP 호스트
  ├─ 로컬 HTTP 또는 비공개 터널 → server.ts
  └─ STDIO → mcp-stdio.ts → 로컬 bridge
                     ↓
                 tools.ts
                     ↓
           Workspace / service.ts
            ├─ 파일 경계 files.ts
            ├─ 승인·실행 대기열
            ├─ 명령 자식 프로세스
            └─ Store → private-io → workspace.json
                     ↕
       Electron main / 제한된 preload IPC
                     ↕
           workroom://app 렌더러
```

## 승인과 실행

등록 시 읽기 전용이며 재시작 시에는 명시적으로 선택한 자동승인 유지 프로젝트만 권한을 복원합니다. `review`는 모든 변경을 확인하고 `delete`는 파일 수정만 자동, `automatic`은 네이티브 경고에 동의한 범위에서 자동 실행합니다. 빠른 시작은 승인 범위 확인 후 폴더·변경 권한·모드를 함께 저장합니다. 유지 체크박스는 기본 해제이며, 기존 승인 폴더가 있으면 범위를 넓히지 않습니다. 미완료 요청은 유지 설정과 관계없이 재시작 시 취소합니다. 모든 셸 명령은 macOS의 승인 폴더·비밀 경로 정책을 따르며, 같은 보호를 지원하지 않는 OS에서는 명령을 거부합니다. 환경변수는 프로젝트 UI의 허용 이름과 명령별 요청 이름의 교집합만 OS 환경에서 가져옵니다.

MCP 제안은 저장된 접수 결과를 빨리 반환합니다. 자동 실행 요청은 최대 15초까지 결과를 기다려 대부분 한 번의 호출로 끝납니다. 이 값은 STDIO 브리지의 30초 요청 제한과 서버 소켓 제한보다 짧게 잡았고, 승인 대기 요청은 기다리지 않습니다. `job_get`도 같은 방식으로 기다립니다. 실행 수명주기는 `pending → queued → running → done/failed/cancelled`이며, 거절은 `declined`입니다. `queued` 또는 `running` 응답으로 성공을 보고하면 안 됩니다. 프로젝트 내 작업은 직렬이고 전역 동시 실행은 2개입니다.

`file_patch`는 접수 시점의 리비전에서 정확한 원문 교체를 적용해 전체 결과를 만든 뒤, 기존 파일 변경과 같은 리비전 검사·승인 판정·원자적 저장을 거칩니다. 요청 동일성은 호출자가 보낸 수정 내용으로 판정하고, 파일에 따라 달라지는 결과 텍스트는 사용하지 않습니다. 완료된 변경은 `resultHash`를 반환해 다음 수정을 다시 읽지 않고 이어 갈 수 있습니다.

## 중복 실행과 복구

요청의 의미 있는 필드를 고정된 순서로 해시합니다. 완료 원문·출력을 정리한 뒤에도 요청 ID, 해시, 상태, 시간이 남아 동일 요청 재시도를 판정합니다. 표시 기록이 가득 차면 종료 기록만 정리하고 활성 요청은 버리지 않습니다. 방지 기록이 10,000개에 도달하면 실행 기록에 없고 하루 이상 지난 가장 오래된 종료 기록부터 삭제합니다. 실행 기록에 남은 요청의 기록은 삭제하지 않으므로 재시작할 때 한도를 넘겨 다시 만들 필요가 없습니다.

취소·권한 회수는 실행 직전에도 확인합니다. 재시작 시 실행 여부가 불확실한 작업은 취소 처리하고 자동 재실행하지 않습니다. 외부 시스템이나 파일에 이미 발생한 부작용을 되돌리는 트랜잭션 시스템은 아닙니다.

## 저장

프로젝트·작업·요청·영수증·활동은 크기가 제한된 JSON 파일에 저장합니다. 여러 변경은 직렬화하며 중요한 상태 전이는 임시 파일, fsync, atomic rename으로 저장합니다. 낮은 중요도의 활동 기록만 배치 처리합니다. 저장 오류는 실행 중지로 이어지고, 잘못된 사용자 입력은 별도로 거부합니다.

이 버전에서 SQLite로 대규모 데이터 마이그레이션을 추가하지 않았습니다. 사용 규모가 한도를 지속적으로 넘는다면 트랜잭션 DB와 전용 기록 정리 정책이 다음 설계 과제입니다. 현재의 파일 단위 저장을 다중 파일 원자적 트랜잭션이나 전원 장애 완전 복구 보장으로 설명하지 않습니다.

## UI와 배포

렌더러는 Node 접근 없이 제한된 IPC만 사용합니다. 자체 프로토콜과 CSP를 사용하고 요청 발신 창·메인 프레임·URL을 검사합니다. MCP 비밀 주소는 일반 UI 데이터에서 제외합니다.

빈번한 변경 알림은 합쳐서 갱신하며, 보이지 않는 창의 갱신과 반복 터널 설치 검사를 줄였습니다. 큰 실행 기록은 40개씩 표시합니다. MCP 파일 일괄 읽기로 호스트 왕복을 줄입니다. 모델 추론이나 ChatGPT 네트워크 지연 자체를 이 최적화가 바꾸지는 않습니다.

프리뷰와 정식 서명 배포는 별도 출력 디렉터리·manifest를 사용합니다. 실제 앱 실행 테스트는 임시 프로젝트·데이터에서 수행합니다. 개발 코드 수정이 현재 실행 중인 앱을 자동 교체하지 않습니다. 공개 릴리스는 별도 서명·공증·배포 주체 준비가 필요합니다.

## 의도적으로 제외한 기능

토큰 추정, ChatGPT DOM/쿠키 자동 수집, 자체 에이전트 루프, 사용량·안전장치 우회, 범용 OS 샌드박스, 자동 업데이트·인터넷 게시, 기록 암호화는 포함하지 않습니다. 자세한 한계는 SECURITY.md와 PRIVACY.md, 실행 증거는 verification.md에 기록합니다.
